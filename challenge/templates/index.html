🗺️ Targets

Three paths. What methods do they accept? Which respond differently?

/vault3 flags here

A locked vault. Policy denies GET. Everything else reaches the handler — but only some reveal data.

Try all eight methods. One leaks data in headers when the body is empty (HEAD). One echoes your request back verbatim (TRACE). One write method returns the flag in a header. Check everything with curl -i.

/vault/backup1 flag here

A backup write path. Endpoint name is not advertised — you have to find it from a hint somewhere else.

Send OPTIONS to /vault. Read every custom X-* header. One names this path directly. Then PUT with no body.

/api/secret1 flag here

Blocks DELETE. But some clients lie about their method using a header.

Send POST to /api/secret with the header X-HTTP-Method-Override: DELETE. The server's filter checks request.method, but the handler respects the override.

🧭 Recon Cheatsheet

Ask first — OPTIONS

curl -i -X OPTIONS https:///vault

Try every method

for m in GET POST PUT PATCH DELETE HEAD OPTIONS TRACE; do
  echo "=== $m ==="
  curl -si -X $m https:///vault | head -20
done

Read headers on HEAD

curl -I https:///vault

Override the method

curl -i -X POST https:///api/secret \
  -H "X-HTTP-Method-Override: DELETE"

Burp workflow

In Repeater, change the first line of a request to test a different method. Use Change request method for quick GET↔POST↔HEAD switching. Check the raw response pane to see headers.

⚠️ Rules

No UI help. There are no buttons that fire exploits. You must build every request yourself in curl or Burp.

No source code. The challenge app is running on your instructor's machine. You only interact with its HTTP responses.

Hints are one-way. Clicking Hint reveals the technique — but only after you've tried. Reading the hint without trying defeats the exercise.

Flags are in headers, not bodies. If a body says "check headers," do it. Most flags never appear as visible text in JSON.
